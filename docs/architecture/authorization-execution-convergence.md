# 授权执行收敛（next）

## 目标与边界

授权规则继续由 `auth.IAuthorizer`、`IPolicy` 与 `AllPolicies` 统一提供。策略在构造期组合，业务调用只描述具名行为；CRUD 与事件溯源保留各自的持久化协议，不新增可任意重排的 Pipeline 框架。

- 单资源业务通过现有 CRUD `Execute` / `ExecuteNew`，不再装配 `app.Command`、Access、Grant 或受限仓储包装。
- 显式状态 ES 增加受保护应用入口，先授权并检查回放基线，业务决定事件后归约实际结果，再在追加前检查范围、保护字段和权威赋值；底层状态仓储仍是组合根的低层工具。
- REST 只消费同一个业务对象的类型化执行方法和授权绑定，不依赖具体 Command 类型。业务方法与绑定必须在该对象中使用同一固定动作。
- 多资源业务由明确的业务服务编排：副作用前预检所有资源，各 Application 仍执行正式授权。后续权限变化导致拒绝时，只有已经证明的同源事务才能保证业务写入全部回滚。外部副作用通过 outbox 或提交后处理；不承诺不同存储的统一事务。不通过 context 布尔值或隐式缓存复用授权决定。
- 移除旧 Command 公共 API 及 CRUD 中的特殊授权复用分支，不保留兼容别名。消息系统 `messaging/command` 不属于本次移除。

## 保留的安全合同

身份与租户可信、范围下推至查询/计数/原子写入、保护字段/权威赋值、乐观版本、两侧迁移、拒绝不调用业务、ES 追加前最终状态检查、事务和审计、提交后失败不可作为未提交重试。

## 已确认缺陷

1. 事件追加前应核对事件名称对应的实际 Go 类型（允许同一类型的值/指针表示），而不只是名称存在；整批校验失败时不能落部分记录。
2. HTTP 独立审计/删除能力须按自身有效页上限归一化页大小后计算偏移，不使用主 CRUD 页上限替代其上限。net/http 与 Gin 共用同一实现与回归合同。

## 实施顺序与验收

1. 保持三仓现有 next 的无关改动，不重写历史。
2. 并行修复事件类型和分页缺陷，加入失败前置回归。
3. 收敛 CRUD 和业务示例，移除 Command 特殊路径，REST 绑定接口化。
4. 补齐显式 ES 受保护入口与提交前检查，示例走同一入口。
5. 整理实体能力文件和测试归属，更新全部引用文档。
6. 三仓分别 build、vet、全量 test、race；Runtime examples-smoke；核验 Core 零外部依赖。若外部数据库或下游不可验证，明确列出，不冒称完成。

main 不改、不合并、不部署。只有 next 通过最终验证才提交；远端推送遵循用户已明确授权。
